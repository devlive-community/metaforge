---
title: 同步执行器
---

MetaForge 执行器是内置的数据同步引擎（旧名称 `Local`，升级时自动迁移）。它在 MetaForge 服务内读取源端查询结果并批量写入目标表，数据集同步和工作流都可以使用。

默认配置是单条查询、单个通道、不限流，适合中小数据量。数据量大时，按下面的说明开启分片并行。

#### 工作方式

一次同步依次经过这些阶段：准备、预计数（可选）、规划分片、传输、收尾（刷新表的行数和大小）。

传输阶段由一条或多条通道并行完成。每条通道有一个读取线程和一个写入线程，各用独立的数据库连接，中间是有界缓冲队列：队列满时读取等待，所以读取不会被写入拖垮，写入也不会让读取停顿。

所有同步进入全局队列排队，同时运行的数量由 `系统设置 > 运行时配置 > 数据集存储` 的 `maxConcurrentSyncs` 控制，默认 4。同一个数据集同一时刻只能有一个未结束的同步。

#### 参数

这些参数可以在 `系统设置 > 运行时配置` 修改默认值，也可以在 `同步数据` 窗口里只对本次同步修改。

**并发与分片**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `concurrency` | `1` | 并行通道数，上限 16。大于 1 时需要分片才有效果 |
| `splitStrategy` | `NONE` | `NONE` 不分片；`AUTO` 在通道数大于 1 时分片；`RANGE` 总是分片 |
| `splitColumn` | 空 | 分片列。留空时取数据集的主键列，其次取排序键列 |
| `splitCount` | `0` | 分片数，上限 256。`0` 表示每条通道 4 个，数据倾斜时快的通道会多处理一些 |

**吞吐与限流**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `fetchSize` | `1000` | 每次从源端拉取的行数。MySQL 和 MariaDB 会自动改用流式读取 |
| `batchSize` | `1000` | 每批写入目标端的行数 |
| `queueCapacity` | `4` | 每条通道缓冲的批次数 |
| `maxRowsPerSecond` | `0` | 所有通道合计每秒读取行数的上限，`0` 表示不限 |
| `maxBytesPerSecond` | `0` | 所有通道合计每秒读取字节数的上限（按值估算），`0` 表示不限 |

**容错与重试**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `maxErrorRows` | `0` | 目标端最多可以拒绝的行数，`0` 表示遇到就失败 |
| `writeRetries` | `3` | 暂时性错误后，同一批重新写入的次数，`0` 表示直接失败 |
| `writeRetryBackoffMs` | `1000` | 第一次批次重试前的等待毫秒数，之后每次翻倍 |
| `maxRetries` | `0` | 暂时性失败后，整个同步自动再运行的次数 |
| `retryIntervalSeconds` | `30` | 整个同步再次运行前的等待秒数 |

**其他**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `preCount` | `false` | 先统计源端总行数，这样从一开始就有进度和预计剩余时间。大表上统计可能很慢 |
| `timeout` | `0` | 运行时间上限（秒），不含排队和暂停，`0` 表示不限 |

#### 分片

分片按分片列的取值范围把查询切成多条，首尾区间开放，键为 NULL 的行单独一片，所以每一行都恰好属于一个分片。

分片列必须是整数或日期时间列，最好有索引且分布均匀。分片内按该列排序读取，没有索引时排序的开销可能抵消并行的收益。

下面这些情况不会报错，会退回单条查询，并在任务日志里说明原因：

- 查询带 `LIMIT`、`OFFSET`、`GROUP BY`、`DISTINCT`、`UNION`、窗口函数或 `WITH`。
- 没有分片列，或分片列不是普通标识符。
- 分片列不是整数或日期时间，或读不出取值范围。
- 数据库不接受分片条件，比如大小写敏感的列名。

各分片是独立查询，不共享快照。如果同步期间源表在变化，结果不是同一时刻的一致视图。

#### 容错

写入失败时按错误类型处理：

- **暂时性错误**（断连、死锁、服务重启）：换新连接，等待后重写这一批，最多 `writeRetries` 次。
- **数据错误**（值太长、类型不符、违反约束）：`maxErrorRows` 大于 0 时，用二分法定位被拒绝的行并跳过，其余行照常写入。被跳过的行全部保存在任务目录的 `<任务名>.dirty.jsonl`，前 20 条显示在运行指标里。超过上限时同步失败。
- **其他错误**（语法错误、无权限、表不存在）：直接失败。

只有失败写入不会留下数据的目标才会跳过坏行：有事务的数据库和 ClickHouse。其他目标遇到坏行时直接失败。

读取或写入遇到暂时性错误、重试仍失败时，如果设置了 `maxRetries`，整个同步会自动再运行。

#### 暂停、继续和重新运行

按分片运行的同步可以暂停。暂停时提交已经成批的行，释放连接并保存断点，继续时重新排队，从断点接着跑。断点按分片键记录，分片键有重复或 NULL 也不会丢行或重复。

失败、超时、已停止或已中断的同步，可以在同步记录页点击 `从断点重新运行`，规则是不能重复写入：

| 情况 | 能否重新运行 |
|---|---|
| 分片运行，有断点 | 可以，从断点继续 |
| 没有分片，已经写入过数据 | 不可以。请清空数据后重新同步 |
| 没有分片，还没有写入数据 | 可以，从头开始 |
| 暂停或等待重试时服务异常退出 | 可以，断点是精确的 |
| 运行中服务异常退出 | 不可以。崩溃前可能已提交断点之后的行，请清空数据后重新同步 |

同一个键的行超过 10 万行时，放不进一批，这次同步会放弃断点，数据照常写完，但不能再暂停或续传。

#### 状态

| 状态 | 含义 |
|---|---|
| 已创建、排队中 | 等待运行 |
| 运行中 | 正在同步 |
| 暂停中、已暂停 | 正在提交在途批次；已保存断点，可以继续 |
| 重试中 | 暂时性失败后，等待下一次运行 |
| 停止中、已停止 | 用户取消 |
| 成功 | 全部完成，表的行数和大小也已刷新 |
| 失败、超时 | 运行出错；超过 `timeout` |
| 已中断 | 运行时服务异常退出 |

排队中、已暂停和重试中的同步可以直接取消。

#### 运行指标

在 `同步记录` 页的 `运行指标` 标签查看：

- **总量**：进度、读取和写入的行数与字节数、总行数及其来源、已运行时间、预计剩余时间、跳过和失败行数。
- **吞吐**：读写速率（最近 5 秒）、平均和峰值速率、最近 120 个采样点的趋势。
- **流水线**：已提交批次、批次重试次数、每批平均耗时、通道数、缓冲队列、读写等待和限流等待时间，以及瓶颈判断（源端读取、目标写入或限流）。
- **分片进度**：每个分片的范围、状态、通道、读写行数、重试次数和耗时。
- **被拒绝的行**：错误信息和行数据样本。

总行数未知时，进度按已完成的分片数估算；没有分片时显示已写入行数，同步结束后才知道总数。

字节数按值估算，只用于观察吞吐，不等于网络流量或磁盘占用。

#### 接口

路径前缀都是 `/api/v1/dataset`：

| 方法 | 路径 | 说明 |
|---|---|---|
| `PUT` | `/syncData/{code}` | 提交同步，请求体可以覆盖上面的参数，返回同步记录 |
| `POST` | `/history/{code}` | 分页查询同步记录 |
| `GET` | `/history/metrics/{id}` | 状态、指标和状态变化记录；`retryable` 表示能否重新运行 |
| `GET` | `/sync/active` | 当前用户未结束的同步 |
| `PUT` | `/history/pause/{id}` | 暂停 |
| `PUT` | `/history/resume/{id}` | 继续 |
| `PUT` | `/history/stop/{id}` | 取消 |
| `PUT` | `/history/retry/{id}` | 重新运行 |

#### 已知限制

写入途中连接断开时，无法确定这一批是否已经生效，重试或续传可能重复这一批，但不会丢行。每条通道最多重复一批。在 ClickHouse 这类没有事务的目标上更容易发生，因为服务端可能已经执行完 `INSERT`。不能接受时，可以把 `writeRetries` 设为 `0`，或使用能去重的表引擎（如 `ReplacingMergeTree`）。
